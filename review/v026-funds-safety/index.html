03

Breaking design

The v0.26 protocol boundary

ONE IDENTITY

FundingSubjectV1

The sole runtime root is the end of an acyclic chain: graph key → setup intent → contributions → graph presign → ceremony → immutable execution policy. Runtime wtxid and block data live only in a derived evaluation binding.

RELEASE PROFILE

S-DFB or C-DIRECT—not both under one id

S-DFB erases the scalar but still lacks its adaptive/output-mask theorem. C-DIRECT deletes DFB but retains the scalar as an ACK-recovery capability inside an audited non-exportable one-shot custodian. Both are blocked; governance must ratify the trust model.

SETUP

Acyclic activation DAG

No certificate hashes itself through a subject. Contributions bind the setup intent; audits and activation bind the final funding root.

CONSENSUS

Vector hash + dead signer

The new graph verifies every ordered preimage. Exact ACK/NACK parents are fully presigned and at least one one-subject signing share is destroyed before funding.

COORDINATION

BFT safety registry

A 2f+1-of-3f+1 total-order service owns admission caps, slot locks, participant burn/readiness, one subject-wide release reservation, publication, and chain state.

RUNTIME

Profile-bound release

Each participant checks Core, CAS-burns, then fully verifies and commits nonsecret readiness. S-DFB requires losing-slot erasure; C-DIRECT requires every one-shot scalar handle to bind the exact proof before one multiplication.

Planning projection 1,493,132 B

Historical S-DFB planning only: two BLS12-381-shaped compact slots plus the old manifest. This is neither a BN462 measurement nor a C-DIRECT requirement. The one-MiB target is subordinate to safety.

Trust-boundary spine

No byte crosses a gate on reputation

  1. P0

    Activate an acyclic subject

    Setup intent, contributions, graph presign, key erasure, ceremony, immutable execution policy, audits, and activation resolve forward to one funding digest.

    no value
  2. P1

    Reserve admission

    The BFT registry atomically reserves subject, outpoint, value, and active count before custody can sign or broadcast funding.

    funding
  3. P2

    Authenticate, derive, lock

    The coordinator parses the intent, derives txid/wtxid and semantic identity, checks Core, then globally locks that one request.

    pre-burn
  4. P3

    Participants burn & become ready

    Each participant structurally binds the proof and checks Core, CAS-burns, then fully verifies and commits signed nonsecret readiness. No honest projective output exists yet.

    no exposure
  5. P4

    Reserve, bind, release once

    The reservation wins against NACK and the alternate slot. S-DFB waits for complete losing-slot erasure. C-DIRECT waits for every custody handle to bind the exact proof, then stages one result, erases the scalar, and only then emits.

    point of no return
  6. P5

    Stage & publish intent

    Exact signed capsule bytes are staged, then replicated inline so rollback cannot destroy a certified publication. This is durability, not the first possible exposure.

    publication
  7. P6

    Consume independently

    The bridge validates the DAG, intent certificate and live txid+wtxid/outpoint/NACK state, then broadcasts the exact parent plus bounded CPFP child.

    consensus

Recovery invariants

  • The BFT CAS lock selects one semantic request across every coordinator and participant.
  • Every participant withholds output until reservation and the complete selected-profile barrier: losing-slot erasure for S-DFB, one-shot custody binding for C-DIRECT.
  • C-DIRECT exposes only module-gated ciphertext before erasure. Exact per-clone or shared-monotonic-domain receipts are required to attest that every inventoried scalar copy is irrecoverable under the selected model; then the result key is released and the final wrapper is replicated and emitted. A no-result path must also tombstone the threshold envelope and erase its forward-secure child-key shares. If power fails after consuming the one output intent but before caching it, the subject remains reserved: no retry and no alternate slot. Funding stays prohibited until a loss-safe timeout is independently qualified for that terminal.
  • NACK seen before reservation blocks release; after reservation it blocks a new publish intent/broadcast. Reorg may resume only the exact path; finality requires depth.
  • Exact objects and nonrecursive finalization envelopes survive rollback through retirement plus the reorg tail.
  • Secret payloads are ciphertext under threshold-HSM retention keys; expiry erases honest managed shares, not an adversary’s memory.
  • A certified publish intent is recoverable byte-for-byte; no retry signs a fresh capsule or selects another vector.
  • Core reorg after release: coordinator stays released; bridge may rebroadcast only the same ACK.
  • Primary and recovery failures are preserved together and page operators.

07

Not defaults

Decisions that change the theorem

CRYPTO + PROTOCOL + OPS

Release trust model

Choose S-DFB with its unproved evaluator theorem, or the separately versioned C-DIRECT profile with audited online scalar custody. Ordinary encrypted storage cannot qualify C-DIRECT.

Before contribution codec
CRYPTO + GOVERNANCE

Native suite backend

The required floor is 128 bits and the curve target is BN462. A curve recommendation or attack ceiling is not an approved suite floor. No reviewed native suite is qualified, and CFRG deliberately leaves BN462 point encoding to the application profile.

Before suite build
PROTOCOL + ECONOMICS

Timeout semantics

Selected research direction: every CounterproofV2 and Owner parent atomically consumes the full counterproof-reserve roster; non-selected reserves are returned exactly to setup-bound beneficiaries, and selection allocates the deposit to recovery. ACK creates the only Slash authorization; timeout conflicts on resolution and contest-slash while omitting claim-payout. Rust/Core reproduce those local edges. The abstract terminal engine enumerates every maximal local branch and proves that valid-withheld and invalid-absent see the same timeout, but policy identity, baseline authority, per-principal allowances, service-fee authority, by-horizon execution, hidden legacy signatures, and stake exclusivity remain unproved.

Local dispositions satisfied; protected-value theorem blocked

08

Build order

Front-load the decisions that can kill the route

  1. 01

    Kill decisions

    Ratify S-DFB versus C-DIRECT, enforce the 128-bit floor, qualify a BN462 backend, and prove timeout/NACK fund preservation. Stop the route if any fails.

  2. 02

    Identity DAG + graph v2

    Strict codecs, exact statement/two-slot budget, vector connector, fixed NUMS keys, txid-stable funding, presign/key erasure.

  3. 03

    Safety registry + admission

    BFT CAS, nonrecursive exact envelopes, readiness/reservation/profile barrier, append-only chain events, risk caps, custody gating.

  4. 04

    Complete proof-suite spike

    Implement the selected DFB or direct-custody release mechanism with the actual curve port and security theorem. Drop the storage target if safety requires it.

  5. 05

    Participants + coordinator + bridge

    Ready-after-burn, profile-bound one-shot release, failover-safe outboxes, typed capsule, independent Core finality, bounded CPFP.

  6. 06

    Live matrix + independent audits

    Crash, fork, reorg, concurrency, admission races, fee pressure, downstream payouts, then staged activation.

FIRST MILESTONE

Do not start with a proof coordinator. First settle the kill decisions, then build the acyclic funding-subject codec and graph-v2 presign theorem.
