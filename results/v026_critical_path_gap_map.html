Five findings

F1 — This is not a coding problem

24 of 28 obligations cannot be discharged by writing software. Staffing this as an engineering push mistakes the bottleneck.

F2 — The SP1/BN254 receipt track is not on the funding path

Protocol doc §14 hard kill criterion 8: “BN254 remains in the proof or conditional-lock trust path” keeps safe_for_funds false. Criterion 9 closes the escape hatch: “a new lock wraps a still-authoritative weaker proof suite.” §1.4 sets a 128-bit floor with a BN462 target and states neither suite is implemented or qualified today; §2 places the current BN254 PositiveLock near 100-bit security with variable-time Python operations.

The subject-bound SP1 work is BN254 Groth16. Recovering that receipt closes the deterministic final Groth16 execution/verification evidence gate and nothing else. Legitimate research evidence — not funds-safety progress, and it must not be reported as such.

F3 — Four decisions gate almost everything

§16 decisions 1–4 (proof-suite floor, S-DFB vs C-DIRECT release profile, timeout/NACK economics, wire profile) sit upstream of the CRYPTO obligation, both identity-layer CODE obligations, and the entire GOV cluster. The doc is blunt about it: “Open decisions are not permission to use defaults. Each one changes the security theorem or economic loss bound.”

F4 — Published evidence tracks the older graph; the live path is unpersisted

Verified in source, not inferred:

  • V026ActivationBlocker — 16 blockers. This is what results/v026_rust_graph_core.json reports, and it is correctly scoped to the v1 assembler it tests.
  • V026ThresholdActivationBlockerV3 — 17 blockers, adding ThresholdAckWitnessAdoptionUnimplemented.
  • v026_admission_v3.rs:36 — V026_BLOCKER_COUNT_V3 = 17. This is the live path.
  • FoundationDB row specs present: v026_admissions.rs (15), v026_admissions_v2.rs (16), v026_ack_witnesses_v3.rs. There is no v026_admissions_v3.rs.

The v3 threshold observation carrying 17 blockers has no persistence envelope at all — the same class of gap already recorded for v1 as current_16_blocker_graph_encodable: false, one generation later, and named by no evidence file.

Report only. Closing this means regenerating evidence and extending the claim boundary. Hand-editing run-generated JSON destroys provenance.

F5 — v0.25.2 blockers are superseded by redesign, not inherited

§2 establishes as implementation fact that v0.25.2 cannot be promoted in place, and §1.8 forbids in-place migration. The seven v0.25.2 funds blockers are historical context. Three of them — native constant-time implementation, independent cryptography audit, independent implementation audit — nevertheless recur as v0.26 acceptance gates. They were never closed; they return under new scope.
