VERIFIED ROOT CAUSES

1. Wrong circuit-version metadata pin.

   Active source:
   /Users/cdjk/github/llm/ranklock/tmp/strata-v026-f94c/crates/proofs/bridge-counterproof/src/subject_receipt.rs

   It currently pins `SUBJECT_BOUND_SP1_CIRCUIT_VERSION_V1` to `v6.2.4`.
   The installed crate is 6.2.4, but the actual SP1 circuit/receipt version is read
   from `sp1-prover-6.2.4/SP1_CIRCUIT_VERSION` and is exactly `v6.1.0`. The network
   artifact also records `v6.1.0`.

2. zkaleido destroys the network proof's committed-values hash during a needless
   round trip.

   Dependency source:
   /Users/cdjk/.cargo/git/checkouts/zkaleido-7822bc7834ae932e/b1c3a5a/adapters/sp1/host/src/proof.rs

   `TryFrom<&ProofReceiptWithMetadata> for SP1ProofReceipt` reconstructs Groth16
   public input 1 using `SP1PublicValues::hash_bn254()`, which is SHA-256. The
   fulfilled proof used SP1's permitted Blake3 public-values hash. Thus
   `host.verify(&receipt)` verifies a reconstructed proof different from the proof
   returned by the network.

   The standalone `SP1Groth16Verifier` is the correct verifier for the canonical
   metadata receipt: it retries SHA-256 and Blake3.
